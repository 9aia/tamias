# CLI

> Generated by `tamias gen-cli-docs` (`cargo run -q -p tamias -- gen-cli-docs`).
> The table below is a hand-written summary; the command emits the full
> reference.

tamias is the **host metaservice**: fetch, install, provision, deploy,
and service-manage content — plus a local/Cloudflare registry.

| Verb | What it does |
| --- | --- |
| `tamias install <ref>` | resolve → fetch → store (runs the content type's **provider** install) |
| `tamias add <ref>` | record in `tamias.yaml` + install |
| `tamias remove <name>` | drop the store entry (cache untouched) |
| `tamias list [--type T]` | installed packages, labels, digests |
| `tamias info <name>` | manifest, source ref, resolved sha, size |
| `tamias update <name>\|--all` | re-resolve the recorded source ref |
| `tamias pin <name> <ref>` | retarget the recorded ref |
| `tamias verify <name>` | digest-check the store vs the record |
| `tamias cache clean [--all]` | evict the fetch cache |
| `tamias deploy <name> [--config <f>]` | run the provider's **deploy** step (unit, hooks, activation) |
| `tamias uninstall <name>` | provider **teardown** + drop the store entry |
| `tamias service {install,enable,disable,status,logs,uninstall}` | the per-user **systemd** unit mechanism |
| `tamias search <query>` | query a (local \| Cloudflare) registry |
| `tamias publish <dir> [--registry <ref>]` | push a package to a registry |
| `tamias registry serve [--addr H:P] [--dir D]` | serve a local registry over HTTP |
| `tamias deploy-registry [--out D]` | write the Cloudflare registry Worker + config |
| `tamias bundle pack <dir>` | dir + manifest → `.tgz` |
| `tamias serve` | ndjson JSON-RPC over stdio (embedding surface) |
| `tamias doctor [--json]` | host diagnostics — store, cache, registry, driver |
| `tamias config [--file f] [--json]` | show the effective config (YAML standard, TOML alt) |
| `tamias version` / `manifest` | machine-readable surface |
| `tamias schema` | print the `tamias.yaml` JSON Schema |
| `tamias gen-cli-docs` | print this CLI reference (markdown) from the parser |

## The provider / driver protocol

A package's content type may name a **provider binary**; tamias shells it and
never links the product crate:

```
<provider> provision {install,deploy,uninstall} --dir <dir> --name <name> [--config <f>]
```

`peregrin-bundle` → provider `peregrin` (`peregrin provision …`). This is the
seed of the **driver system** (see the org-ledger `P10` plan): Rust
`tamias-driver-<name>` binaries, discovered on `PATH`/`drivers/`, JSON over
stdio.
