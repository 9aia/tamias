Expand description

Redeploy a surviving same-(scope, name) sibling’s declared bins[] after removed’s store entry dropped — the bins half of version-aware teardown (the T-029 rule applied to PATH surfaces). Shim markers and the shared bin-alias are keyed on package identity (@scope/name, not the versioned label), and unlink_payload_bins drops that alias unconditionally, so the cleanup half of a remove/uninstall strips commands and payload links every coexisting version owns. entries is the post-removal store scan; removed only identifies the (scope, name) group (its own dir is excluded even if the scan still lists it).

The survivor picked is the newest semver precedence among siblings still declaring bins[] — the same ordering tamias_core::plan_prune keeps, so prune’s “latest” and the redeployed bins agree. Siblings whose version isn’t semver sort behind parseable ones; when no candidate parses, the label-greatest one redeploys so the group’s commands don’t dangle on a removed label. Deploying only the newest keeps the shared alias pointed at one entry dir — payload-bin links resolve through it, and a second version’s differing bins[] set would leave stale links either way. None when no same-group sibling remains or none declares bins — the plain cleanup already ran, nothing to restore.

Best-effort by contract: callers warn on Err, never fail the completed removal. Deploy collisions follow deploy_bins rules — last-deploy wins over other tamias packages, foreign files conflict. Note this redeploys declared bins even for a survivor installed --no-bins: deploy state isn’t recorded per version, and the identity-shared surfaces can’t tell the versions apart — tamias bin destroy is the opt-out.
