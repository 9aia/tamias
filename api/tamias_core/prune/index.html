Store pruning — the pure half of tamias prune.

The store keeps every version ever installed (name@old alongside name@new); old versions are legitimate rollback targets, so pruning is always an explicit operator act. plan_prune decides what is superseded — semver-max per (scope, name) group — and the surfaces (CLI, TUI, serve) decide how removals run through the same uninstall path remove/uninstall use.

Conservative by construction: entries whose version isn’t valid semver (unversioned digest labels, hand-edited records, odd version strings) are never pruned and never count as the “latest” to keep — they land in PrunePlan::skipped with the reason.

latest_version
The newest semver-precedence entry in entries — the same ordering plan_prune keeps at keep = 1: max major/minor/patch/prerelease ignoring build metadata, the store label breaking precedence ties. Entries without a parseable semver version: are ignored; None when entries is empty or none parse. Used where a survivor must be picked deterministically — e.g. redeploying a removed version’s bins from the newest same-package install left behind.
plan_prune
Group store entries by (scope, name) and pick the superseded ones: within each group the newest keep distinct semver precedences survive (all entries sharing a kept precedence are kept — build-metadata ties can’t split a version), everything older is a PruneRemoval. Groups with a single entry are no-ops; entries without a parseable semver version: are PruneSkipped, never removed.
