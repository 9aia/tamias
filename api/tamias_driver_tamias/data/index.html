data — one read of tamias state per wire op.

The driver is a reader: every view/query resolves the tamias roots, lists the install store’s .tamias-store.json records, scans <tamias-home>/drivers/ + PATH for tamias-driver-* executables, and counts fetch-cache entries — the same on-disk layout tamias list/tamias info/ tamias doctor read. No mutations: tamias install/remove/ cache clean stay the write surface; this crate only needs what those verbs already show.

Root resolution (first hit wins) — mirrors the tamias CLI’s store_root()/cache_root()/registry_root() plus the tamias-driver crate’s tamias_home()/drivers_dir():

  • params.home — a tamias-home override: store=home/store, registry=home/registry, drivers=home/drivers, cache=home/cache (the CLI keeps the fetch cache outside the data home via TAMIAS_CACHE/XDG; under an explicit home param home/cache is the driver’s convention).
  • params.store/cache/registry/drivers — per-root overrides that beat home for that root only.
  • env/defaults otherwise: $TAMIAS_HOME → $XDG_DATA_HOME/tamias → ~/.local/share/tamias for home+store+registry+drivers; $TAMIAS_CACHE → $XDG_CACHE_HOME/tamias/fetch → ~/.cache/tamias/fetch for the cache; ./.tamias/* is the no-env fallback for all of them — the store/cache/registry roots here follow the CLI, and tamias-driver::tamias_home() falls back to ./.tamias too, so ./.tamias/drivers is where the drivers scan lands.

When the store can’t be read at all, Snapshot::error carries the reason and every query degrades to an {"error": …} payload — the wire stays ok:true so hosts render the failure inline.
